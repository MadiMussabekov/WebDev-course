# Space Bounty Hunters API

A REST API for space bounty hunters: a database of wanted criminals and a journal of hunting attempts.

**Built with:** Django REST Framework · PostgreSQL · Docker Compose (same stack as my Midterm project).

## How to run (database setup and import)

You only need Docker Desktop.

```bash
cp .env.example .env     # skip if .env already exists
docker compose up --build
```

| Page | URL |
|---|---|
| Swagger UI (try every endpoint in the browser) | http://localhost:8000/api/docs/ |
| API | http://localhost:8000/api/ |
| OpenAPI schema | http://localhost:8000/api/schema/ |

When the `api` container starts, it:

1. creates the tables in PostgreSQL (`python manage.py migrate`);
2. fills the database with sample data if it is empty (`python manage.py seed_bounty`):
   **7 criminals and 12 hunt logs**;
3. starts the server (Gunicorn).

To reset the sample data:

```bash
docker compose exec api python manage.py seed_bounty --force
```

To stop: `docker compose down` (data is kept). `docker compose down -v` also deletes the data.

## Database models

**WantedCriminal**

| Field | Type | Notes |
|---|---|---|
| `id` | bigint, PK | |
| `name` | varchar, nullable | real name, may be unknown (`null`) |
| `nickname` | varchar | alias |
| `reward` | decimal | bounty, `>= 0` |
| `last_known_latitude` | float, nullable | -90..90 |
| `last_known_longitude` | float, nullable | -180..180 |
| `last_known_note` | text | text note about the last known location |
| `difficulty` | small int | 1..10 (validator + DB check constraint) |
| `armed` | boolean | |
| `has_crew` | boolean | |
| `escape_master` | boolean | |

**HuntLog**

| Field | Type | Notes |
|---|---|---|
| `id` | bigint, PK | |
| `criminal_id` | FK → WantedCriminal | `ON DELETE CASCADE` |
| `success` | boolean | was the criminal captured |
| `notes` | text | |
| `created_at` | timestamp | set automatically by the server (`auto_now_add`), read-only |

**Relationship:** one-to-many. One `WantedCriminal` has many `HuntLog`s (`criminal.hunts`).

## Endpoints

### Wanted criminals

| Request | Description |
|---|---|
| `GET /api/criminals/` | List of criminals |
| `GET /api/criminals/{id}/` | One criminal, including its hunt logs |

Query parameters for the list (they can be combined):

| Parameter | Example | Description |
|---|---|---|
| `min_reward` | `5000` | reward >= value |
| `max_reward` | `100000` | reward <= value |
| `armed` | `true` / `false` | |
| `has_crew` | `true` / `false` | |
| `escape_master` | `true` / `false` | |
| `sort` | `reward` / `-reward` | ascending / descending by reward |

Example: `GET /api/criminals/?min_reward=5000&armed=true&sort=-reward`

### Hunt logs (journal)

| Request | Description |
|---|---|
| `GET /api/hunts/` | List of hunt logs; `?criminal_id=5` filters by criminal |
| `GET /api/hunts/{id}/` | One hunt log |
| `POST /api/hunts/` | Record a capture attempt |
| `PATCH /api/hunts/{id}/` | Update `success` and/or `notes` |
| `DELETE /api/hunts/{id}/` | Delete a hunt log |

Example POST body:

```json
{
  "criminal_id": 3,
  "success": false,
  "notes": "Target escaped through an asteroid field."
}
```

`created_at` is generated by the server. If the client sends it, it is ignored.

### Status codes

| Code | When |
|---|---|
| `200 OK` | successful GET / PATCH |
| `201 Created` | hunt log created |
| `204 No Content` | hunt log deleted |
| `400 Bad Request` | invalid body (unknown `criminal_id`, missing field, wrong type) or invalid query parameter (`min_reward=abc`, `sort=name`, `armed=maybe`, `criminal_id=abc`) |
| `404 Not Found` | criminal or hunt log does not exist, or the id is not a number |
| `405 Method Not Allowed` | e.g. `PUT` on hunts, `POST` on criminals |

## Postman

1. Start the API with `docker compose up --build`.
2. In Postman click **Import** and choose `postman/BountyHunters.postman_collection.json`.
3. Click **Run collection**. All 25 requests have tests and pass.

The collection has three folders:

- **Wanted Criminals**: listing, filtering, sorting, details, plus invalid requests (not found, bad filter, bad sort).
- **Hunt Logs (CRUD)**: list, filter by criminal, create, get, update (PATCH), delete. It also checks that a
  client-sent `created_at` is ignored. Created records are deleted at the end, so the collection can be run many times.
- **Invalid Requests**: unknown criminal, missing `criminal_id`, wrong `success` type, non-numeric id, not found id,
  bad `criminal_id` filter.

It can also be run from the command line: `npx newman run postman/BountyHunters.postman_collection.json`.
